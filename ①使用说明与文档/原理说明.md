# 原理说明（技术原理）

> 本文说明本工具「怎么做到的」：架构、插件机制、视频提取与下载引擎、反风控设计。

## 一、总体架构

```
gui.py / main.py
   │  界面与流程编排
   ▼
download_flow.py      下载流程编排（搜索 → 收集 → 下载 → 清单）
   ▼
video_crawler.py      爬虫框架（浏览器管理 / Cookie / 属性转发）
   │  调用站点插件
   ▼
sites_data/*_crawler.py   站点插件（搜索 → 剧集表 → 每集视频地址）
   ▼
video_downloader.py   下载引擎（直链分段 / HLS 分片 / AES 解密 / ffmpeg 合成）
```

- **GUI/CLI 双入口**：`gui.py`（两步操作界面）、`main.py`（命令行）。
- **浏览器自动化**：基于 DrissionPage 驱动 Edge/Chrome，独立调试端口 + 临时配置目录，支持有头/无头、Cookie 注入。

## 二、插件机制（站点即插即用）

`site_discovery.py` 扫描 `sites_data/*_crawler.py`，类名以 `Crawler` 结尾且含 `SITE_NAME` 即自动注册到站点下拉列表。

插件实现三个核心方法即可接入：

```python
class XxxCrawler:
    SITE_NAME = '站点名'
    SITE_URL = 'https://...'
    def search_series(self, name, series_id=None): ...   # 打开详情页
    def get_episode_count(self, target_tab): ...          # 总集数
    def collect_episode_videos(self, target_tab, episode_start, episode_end,
                               max_threads, progress_callback, keyword=None): ...
        # 返回 [{episode_num, title, video_url, video_type, referer}]
```

`video_crawler.py` 的 `__getattr__` 把插件新方法自动转发给 GUI，插件扩展无需改主程序。

## 三、视频地址提取原理

| 站点/模式 | 原理 |
|-----------|------|
| 樱花动漫 | 详情页正则提取全部播放链接（`.html` 尾数字 / `-(线路)-(集数)` / 斜杠三段三种格式），requests 并发批量抓播放页，页面内 `<iframe>` 播放器递归提取（最多2层），`player_*` 变量名泛化；失败回退浏览器逐页 |
| AGE动漫 | 搜索 `/search?wd=` → 详情 `/detail/{id}` → 播放 `/play/{id}/{sid}/{nid}`，多线路去重取 sid 最小；播放页 iframe → 云播放器 `jx.wuzhoupai.com/vip/?url=...` → 页面内 `<video>` 直链 |
| 哔哩哔哩 | 搜索定位 → 详情页提取 `__playinfo__` JSON → **DASH 双流**（视频流 + 音频流分开下载）→ ffmpeg 合成单 mp4；大会员需 Cookie |
| 抖音精选 | 精选页 SPA，页面内**同步 XHR** 请求 feed 接口 `aweme/v2/web/module/feed`（带 Cookie，免破解签名）→ JSON 中 `video.play_addr.url_list` 即 mp4 无水印直链（签名约6小时有效）；持续随机抓取 + 去重累积 |
| 自动扫描 | 打开地址 → 列表页自动滚动触发懒加载 → 递归深入（最多4层/80页）；页面脚本匹配 `.m3u8`、`<video>/<source>` src、`<iframe>` 内递归、`.mp4` 直链 |
| 华丽装饰 | 播放路由 `/vodp/{id}-{sid}-{nid}.html`；搜索 `/vodsearch/{kw}-------------.html`（无问号）；播放器 `api.ldyun.cc` 乐多源 iframe，`player_*` 变量名提取 |

通用提取手法（`generic_crawler.py`）：页面脚本正则 `.m3u8` → `<video>/<source>` src/data-src → `<iframe>` 播放器递归（≤2层）→ `.mp4/.webm/.mkv` 直链。

## 四、下载引擎原理

- **直链下载**：requests 流式；多线程分段加速（自动探测服务器 `Range` 支持，不支持自动回退单线程；<1MB 不分段）。
- **HLS(m3u8) 下载**：解析 m3u8 → 选最高清晰度 → 并发下载分片（速度档决定并发数）→ 分片 AES-128 解密（pycryptodome）→ 合并 .ts → **ffmpeg 封装 mp4**（未装 ffmpeg 则保留 .ts）。
- **失败重试与容错**：每集重试3次（退避 0.8s/1.6s/2.4s）；分片连续失败≥7 快速取消改 ffmpeg 整段兜底；部分集解析失败不再整体报错（成功集先交付 + 日志列失败集）。
- **进度反馈**：总进度 / 当前集分片进度 / 实时网速；集间休息 2s。
- **自动清单**：下载完生成 `扫描结果.json`（每集标题、地址、状态、文件）。

## 五、容错与反风控设计

| 问题 | 对策 |
|------|------|
| 弱站并发打爆服务器（华力站 8线程全站 ERR） | `_bulk_collect` 并发钳制 ≤4、每集重试、成功判定放宽 |
| 播放器接口偶发空响应 | `_resolve_iframe_http` 重试3次、空响应/短页面也重试；浏览器兜底 iframe 轮询 5→8 次 |
| 网站风控封 IP（AGE 登录都上不去） | **模拟人手**：随机延时（3.5-6s 开页、2-4.5s 阅读）、4 个浏览器 UA 轮换、完整 `Sec-Fetch-*` 请求头、模拟滚动；AGE 收集降为串行 1 线程 + 1.5s 间隔 |
| 部分集失败整批报错 | `collect_episode_videos` 部分成功不再 raise，失败集跳过并日志 |
| 浏览器兼容（DrissionPage） | JS 抓接口用**同步 XHR + return 前缀**（适配 `run_js` 函数体包装）；`VideoCrawler.__getattr__` 转发插件新方法 |

## 六、改造映射（漫画下载器 → 视频下载器）

| 原（漫画） | 新（视频） |
|-----------|-----------|
| 章节（chapter） | 剧集（episode） |
| 逐章提取图片 URL | 逐集提取视频 URL |
| 图片并发下载 | 直链流式 + HLS 分片/解密/合并 |
| 章节文件夹命名 | 集号+标题命名 + 扫描结果清单 |
| 单页图片提取 | 递归自动扫描 + 站内搜索定位 |
